# 01 · 方案详解（架构与原理）

## 1. 目标

多 Agent 环境下，让**一份技能数据**被所有 Agent 共用，做到：

- 安装一次，处处生效；
- 更新一次，处处生效；
- 删除一次，处处消失（⚠️ 见风险文档）；
- 新增一个 Agent，一条命令接入。

## 2. 核心机制：NTFS 目录联接（Junction）

Windows 的**目录联接（Junction，重解析点的一种）**允许把目录 A 变成指向目录 B 的"别名"：

```text
C:\Agent\skills ──(Junction)──▶ C:\Shared\skills
```

访问 `C:\Agent\skills` 时，NTFS 透明地把请求转发到 `C:\Shared\skills`。对上层应用来说，
它看到的只是"这个目录里有哪些文件"——**应用无法感知，也无需感知**联接的存在。

### 2.1 为什么是 Junction，而不是其他方式

| 方式 | 原理 | 一次安装处处生效 | 需管理员 | 改动同步 | 备注 |
| --- | --- | :-: | :-: | :-: | --- |
| 复制到每个目录 | 各自维护副本 | ❌ | ❌ | ❌ | 版本漂移、漏更新 |
| 符号链接 `mklink /D` | 链接到目标路径 | ✅ | ✅（或开发者模式） | ✅ | 提权门槛高 |
| **目录联接 `mklink /J`** | 重解析点到目标路径 | ✅ | ❌ | ✅ | 本方案选择 |
| 环境变量 | 改配置指向 | 仅对支持变量的工具 | ❌ | — | 多数 Agent 不支持 |
| 目录硬链接 | NTFS 不支持 | — | — | — | 不存在此能力 |

关键结论：**Junction 是 Windows 上唯一"免管理员 + 免复制 + 即时同步"的组合**。

### 2.2 Junction 的关键性质

1. **读写穿透**：通过任一入口读、写、建、删文件，实际都落在共享库；
2. **绝对路径目标**：Junction 记录的是目标的绝对路径。共享库被移动/重命名后，联接会失效（可用 `verify.ps1` 检测，重建即可）；
3. **删除的是"门"还是"数据"**：
   - 删除**联接本身**（`cmd /c rmdir <联接路径>` 或 `Remove-Item -Force` 不带 `-Recurse`）→ 只拆掉别名，共享库数据原封不动；
   - **绝不能**对联接使用 `Remove-Item -Recurse` / `robocopy /MIR` 等递归操作 → 会**穿透联接删除共享库里的真实数据**。
4. **跨卷**：Junction 支持跨 NTFS 卷（`C:` ↔ `D:` 均可），比旧式硬链接灵活；
5. **免提权**：创建 Junction 不需要管理员权限，也无需开启开发者模式。

## 3. 数据流

```text
┌─────────────────────────────┐
│  共享技能库（唯一数据源）       │  C:\Users\<you>\skills\shared\
│  ├─ tdd/SKILL.md            │
│  ├─ grill-me/SKILL.md       │
│  ├─ code-review/SKILL.md    │
│  └─ ...                     │
└───────────▲─────────────────┘
            │ NTFS 重解析（Junction，透明转发）
  ┌─────────┴─────────┬─────────────┬──────────────┐
  ▼                   ▼             ▼              ▼
┌──────────┐   ┌────────────┐ ┌──────────┐   ┌──────────┐
│ Doubao   │   │Claude Code │ │  Codex   │   │  Cursor  │
│.user_sk… │   │.claude\…   │ │.agents\… │   │.cursor\… │
└──────────┘   └────────────┘ └──────────┘   └──────────┘
```

每个 Agent 的技能根目录都是一个 Junction，指向同一个共享库。**数据只有一份**。

## 4. 迁移语义（已有技能怎么办）

`setup.ps1` 对每个配置的 Agent 根目录执行：

1. 目录**不存在** → 直接创建 Junction；
2. 目录**已是 Junction** → 校验目标是否为共享库，是则跳过，否则报错（避免破坏已有方案）；
3. 目录是**真实目录**且包含内容 → 把内容**移动到共享库**（同名冲突：保留共享库现有版本，冲突项写入报告，绝不覆盖）→ 删除空目录 → 创建 Junction。

## 5. 生效时机

绝大多数 Agent 在**会话启动时**扫描技能目录并建立索引。因此：

- 搭建/改动后，**重启 Agent 会话**（新开会话）即可看到全部技能；
- 少数 Agent（如 Claude Code）支持运行中的动态发现，通常也会在会话内自动识别。

## 6. 适用范围与边界

| 维度 | 说明 |
| --- | --- |
| 平台 | Windows（NTFS）。macOS/Linux 用 `ln -s` 符号链接实现同一思路 |
| 机器 | 单机内共享；跨机器请用 git 仓库 + 同步脚本（方案二思路） |
| 技能类型 | 通用 Prompt 型技能（SKILL.md + 资源文件）可全平台共享 |
| 不通用 | Agent 专属语法：Claude Code 斜杠命令/插件、OpenClaw 专属配置、平台绑定 MCP |
| 数据量 | 技能通常为 KB~MB 级文本，单份存储几乎无空间成本 |

## 7. 与"方案二（中心仓库 + 同步脚本）"的对比

| 对比项 | 方案一 · Junction（本项目） | 方案二 · 同步脚本 |
| --- | --- | --- |
| 一次安装处处生效 | ✅ 即时 | ✅ 需重跑脚本 |
| 改动同步 | 自动 | 手动触发 |
| Agent 间隔离 | 弱（共享命运） | 强 |
| 回滚 | 简单（拆联接即可） | 需保留副本 |
| 多机器 | ❌ | ✅ |
